The problem

Review bots write a lot. Developers act on some of it.

We read every inline bot comment on 30 merged pull requests of pingdotgg/t3code, an open TypeScript and Rust repo. Each comment then costs a person time to read and judge.

37%

of the 383 top-level comments were followed by a code change on the commented lines.

How it works

Two checks, one comment, and a person at the end.

A fast check runs plain rules with no model. A proof run lets a model propose findings, then makes each one earn a test. Only proof reaches the gate.

Fast check

Deterministic and cached. No model, no PR code. The target is under 2 minutes p95; it is not measured yet. ACTION_MODE 5.1

Proof run

A finding needs a test that fails twice on the PR head and passes on the fixed tree. One red run is not proof. A build error is not proof. A6 in the tracker

No model in the gate

A model may propose. Plain Go rules decide from the proof. A missing fact is unknown, never a pass. STRATEGY 5

A person approves

The approval counts only on the head commit and only from a person who did not write the change. approval clause

internal/domain/external
test integrity

Tests cannot be gamed quietly

  • Pinned tests are read-only until a policy owner approves.
  • Weakened tests and tautological asserts are flagged.
  • A test that mocks the code it should check is flagged (Go, Python, JS and TS).
  • The fail-twice rule: two red runs on the head, green on the fix.
internal/domain/testintegrity
sandbox

PR code runs as a separate, locked-down user

On a GitHub-hosted runner, run 44910812111 blocked every escape class. Tests run with no network; installs reach only an allowlisted registry through a proxy. The run had 34 fetch and 36 execution probe tests, 0 unknown. The probes cover the parent's environment, other users' files, host sockets, D-Bus, docker, ptrace, setuid, namespaces, eBPF, cgroups and the network.

We also found a real escape and closed it: the host's shared /dev/shm on an Azure host (run 44909950640). Each phase now gets its own tmpfs. When the hardening does not take, the sandbox refuses to run and the proof is unknown. It never runs unsafe.

Not verified: load stress, a fork bomb, non-Go package managers, self-hosted and ARM runners.

Shadow mode and break-glass

ACTION_MODE 5.4
speed

Run only the tests a change can affect

Heimdall's own suite on 5 real commits: 106.7 s to 13.1 s. It falls back to the full suite on go.mod, vendor or an unknown file. On echo and client_golang the gain was small; we say so.

BENCH, test selection
cost

A cost guard before every call

The worst-case cost of a call is checked against the cap before the call is made. Errors 429 and 5xx get up to 3 attempts with backoff, inside the same cap.

STRATEGY 5, why we win

Install · coming next

The GitHub Action is not shipped yet.

This is the planned proof workflow from the design. It is a preview. Names and inputs can change before release.

  1. Add the workflow and your model key as a secret.
  2. Run two weeks in shadow mode: the check posts "would block because" and blocks nothing.
  3. Make heimdall/fast a required check when the team trusts it.

ACTION_MODE 3.2, the three workflows

PREVIEW.github/workflows/heimdall-proof.yml
# PREVIEW. Not released. Planned from docs/product/design/ACTION_MODE.md 3.2.
# The action name and its inputs are placeholders.
name: heimdall-proof
on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]

permissions:
  contents: read
  pull-requests: read

jobs:
  proof:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      # Pinned by full SHA. The action checks the binary's SHA-256.
      - uses: heimdall/action@<full-commit-sha>   # placeholder
        with:
          mode: proof
          model: deepseek/deepseek-v4-flash         # any OpenAI-compatible id
          base-url: https://openrouter.ai/api/v1
        env:
          # The key is set on this one step, never on the job.
          HEIMDALL_MODEL_KEY: ${{ secrets.HEIMDALL_MODEL_KEY }}
