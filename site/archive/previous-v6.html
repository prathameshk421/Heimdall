"Changed" means a later commit in the same PR touched the commented lines. That label is a proxy: a fix on a nearby line can be missed, and a change is not proof the bug was real. Method and limits.

How it works

Three steps. Only proof decides.

1

Collect

Heimdall reads every review comment on the PR: its own and other bots'. Why

2

Prove

Each finding needs a test that fails twice on the PR and passes on the fix. One red run is not proof. A build error is not proof. Rule

3

Decide

Proven findings block. Unproven ones are not shown and are counted. A person approves the exact commit. Rule

FAQ

Good questions.

Does it replace our AI reviewer?

No. Keep CodeRabbit, Copilot, Bugbot or any other bot. Heimdall referees their findings, and its own, with the same proof rule. Source

What if Heimdall is wrong?

Unproven means not shown, not false. A test can prove a bug is real, but never that a finding is false. Anyone can open the list of unproven findings and read them. Source

What about an emergency?

A named person posts a break-glass with a reason. It is recorded, and it shows as open until another approver reviews it. An agent cannot use it. The record is built; the command ships with the Action. Source

What does it cost to run?

You pay your own model provider. Before every model call, Heimdall checks a worst-case cost bound against your cap. A call that could pass the cap does not run. Source

Where does our code go?

Nowhere new. Heimdall runs on your VM today, and in your CI when the Action ships. Tests run with no network. Only your chosen model endpoint sees the code it reads. Source
