Why Heimdall

Two habits put bad code on main.

Agents write code fast. Review did not get faster. Teams fill the gap with two shortcuts, and both let bad code through.

Habit 1

The quick LGTM

Pull requests get bigger. Reviewers do not read every line, so they write "LGTM" and approve. That approval does not prove that the change is correct.

91%longer review time, with 98% more pull requests, in teams that use AI tools.Faros AI engineering report
Habit 2

Agents that grade their own work

One agent writes the code, the tests and the review. It agrees with itself. Its tests check what the code does. They do not check what the ticket asks for.

83.8%of pull requests from agents get merged. A merge is not a proof.AIDev dataset, 932,791 agent pull requests

Heimdall stops both.

The name

The guard who hears the grass grow.

In the old stories, Heimdall guards Bifröst, the bridge to Asgard. He needs less sleep than a bird. Nothing crosses the bridge without his permission. Your main branch needs a guard like that.

How it works

From ticket to main in four steps.

You write the code and answer questions. Heimdall does the rest in your team chat. It starts when a Jira ticket moves to In Progress. It stops when the GitHub check turns green.

1Before the code

A separate agent writes the tests.

Heimdall opens a room for the ticket. The test agent asks you up to three questions. Then it writes tests that fail. It never sees your branch, so it tests the ticket, not your code. The tests are locked. Nobody can delete them to get a pass.

2At the gate

Slop stops at the door.

Before a reviewer sees the pull request, plain code checks it. It must link a ticket. It must change fewer than 400 lines. It must change only the files in the agreed behaviour. It must add tests. If one rule fails, the pull request goes back with that rule.

3The review

Reviewers from other teams, with their own context.

You choose the reviewers. Each reviewer's agent joins the room with its own name. It knows what that person owns, the rules that must stay true, and the past incidents. Each finding must have evidence: a failing test, a file and line, or a recorded decision.

A human approves. Then the check turns green.

The gate

No model decides the merge.

Agents collect the evidence. A short function decides. It has five conditions, and you can read all of it. Turn the conditions on and off to see the result.

func Open(pr PullRequest) (bool, []string) {  var unmet []string  if !pr.Ticket.BehaviourApproved {    unmet = append(unmet, "behaviour not agreed")  }  if !pr.LockedTests.Pass() || !pr.CI.Green() {    unmet = append(unmet, "tests or CI failed")  }  if !pr.Slop.Passed {    unmet = append(unmet, "slop check failed")  }  if pr.Findings.Open() > 0 {    unmet = append(unmet, "findings not closed")  }  if pr.Approver == "" || pr.Approver == pr.Author {    unmet = append(unmet, "no human approval")  }  return len(unmet) == 0, unmet}

Set up

Set it up with one prompt.

Copy the prompt. Paste it into the coding agent that you use in your repository. The agent does the setup and asks you before it saves your context.

setup-prompt.txt
Set up Heimdall for this repository.

1. Clone https://github.com/prathameshk421/flip_the_switch_hackathon and read the README.
2. Install the Heimdall skills from the skills/ folder.
3. Connect to Switch. Enroll this machine as a host, or use the always-on host.
4. Make a draft of my context pack from CODEOWNERS, the git history and my notes. Show it to me. Do not save it before I approve it.
5. Connect GitHub, Jira and our team chat (Mattermost or Microsoft Teams).
6. On main, add "heimdall/gate" as a required status check.
7. Tell me what you did and what I must do next.

Three things to do

  1. Copy the prompt.
  2. Paste it into your coding agent in the repository.
  3. Read your context pack and approve it.

It takes about 15 minutes for each developer.

Questions

Asked at the gate.

Is this another AI code reviewer?

No. An AI reviewer comments on a diff. Heimdall starts at the ticket and writes the tests first. Each reviewer brings one team's context. A required GitHub check stays red until plain code says that all conditions are met.

Can an agent approve a merge?

No. Agents find problems and fix them. A human who is not the author approves. Only the gate can turn the check green, and the gate is plain code.

Why can the test agent not see my branch?

So that it tests the ticket, not your code. If the tests come from the code, they pass when the code is wrong. Tests from the ticket fail until the code does what the ticket asks.

What if a reviewer agent is wrong?

Each finding must have evidence. The author's agent can close a finding with a reason. If the two sides do not agree, a human decides in the room.

Can one team see another team's memory?

No. The server limits each agent to the teams that it belongs to. Personal context packs never go into team memory.

Does a green check mean that the code is safe?

It means that the change has evidence and a human approved it. Heimdall makes merges safer. It does not replace your CI or security checks, and it does not promise code without bugs.
